# Backend Tools From Scratch

### 10 tools. 10 real backend problems.

> Building small, production-minded tools to become a better backend engineer.

---

## 🛠️ The Projects

### 01 — API Tester

**Test APIs from the terminal.**

Send requests, inspect responses, headers, authentication, status codes, and latency without opening a GUI.

**What you'll learn:**

* HTTP fundamentals
* Request/response handling
* Headers & authentication
* Error handling
* CLI/tool design

---

### 02 — Log Analyzer

**Turn messy backend logs into useful signals.**

Analyze logs to find errors, group failures, identify slow endpoints, and spot patterns quickly.

**What you'll learn:**

* Log parsing
* Pattern detection
* Data processing
* Error aggregation
* Performance analysis

---

### 03 — JWT Debugger

**Debug authentication without guessing.**

Inspect JWT headers, claims, expiration, and token validity to understand exactly what's happening with authentication.

**What you'll learn:**

* JWT structure
* Encoding & decoding
* Authentication concepts
* Token expiration
* Security considerations

---

### 04 — Redis Inspector

**See what's actually happening inside Redis.**

Inspect keys, values, data types, TTLs, and cached application state from one developer-friendly tool.

**What you'll learn:**

* Redis fundamentals
* Key/value data
* TTLs & expiration
* Caching
* Debugging application state

---

### 05 — Database Explorer

**Explore a database from one developer tool.**

Inspect tables, schemas, indexes, rows, and run useful queries without constantly switching between tools.

**What you'll learn:**

* Database metadata
* SQL
* Schemas & tables
* Indexes
* Query execution

---

### 06 — Webhook Debugger

**See exactly what external services are sending you.**

Capture, inspect, store, and replay webhook requests from services like payment providers or GitHub.

**What you'll learn:**

* HTTP webhooks
* Request inspection
* Event-driven architecture
* Payload handling
* Replay & debugging workflows

---

### 07 — Rate Limiter

**Control how often clients can hit your API.**

Build a real rate-limiting system and explore how requests can be tracked and restricted.

**What you'll learn:**

* Rate limiting algorithms
* Request tracking
* Redis
* API protection
* Distributed systems concepts

---

### 08 — Backend Monitor

**Know when your backend is actually unhealthy.**

Monitor APIs, databases, Redis, latency, and critical services from one place.

**What you'll learn:**

* Health checks
* Service monitoring
* Timeouts
* Failure states
* Basic observability

---

### 09 — Job Queue

**Build a system for running background work reliably.**

Create a queue that can process jobs using workers, retries, delayed execution, and failure handling.

**What you'll learn:**

* Background jobs
* Workers
* Queues
* Retries
* Delayed jobs
* Failure handling

---

### 10 — Backend Doctor

**Find out what's wrong with your backend.**

Combine logs, service health, database state, Redis, and application errors to diagnose backend problems.

**What you'll learn:**

* System diagnosis
* Correlating failures
* Debugging workflows
* Observability
* Production thinking
* Combining multiple backend systems

---

# 📈 The Progression

### Developer Utilities

**API Tester → Log Analyzer → JWT Debugger**

Learn how to build tools around everyday backend workflows.

↓

### Backend Infrastructure

**Redis Inspector → Database Explorer → Webhook Debugger**

Start interacting with the systems behind modern applications.

↓

### Production Systems

**Rate Limiter → Backend Monitor → Job Queue**

Deal with reliability, performance, scale, and failure.

↓

### The Final Challenge

**Backend Doctor**

Bring everything together into one system designed to answer:

> **"Something is broken. What is it, and why?"**

---

# 🚀 The Challenge

## Build → Test → Break → Improve → Ship

For every project:

### 1. Build

Create a working version.

### 2. Test

Put it against realistic scenarios.

### 3. Break

Intentionally introduce failures and edge cases.

### 4. Improve

Handle the problems like a real production tool.

### 5. Ship

Document it and publish the project.
